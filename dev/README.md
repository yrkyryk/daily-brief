# dev docs

대규모 태스크의 계획·컨텍스트·체크리스트를 보관한다. 컨텍스트가 끊겨도
`dev/active/` 만 읽으면 하던 일을 이어갈 수 있게 하는 것이 목적이다.

## 구조

```
dev/active/<task-name>/     진행 중
dev/completed/<task-name>/  끝난 것
```

각 태스크 폴더는 보통 세 파일을 가진다.

| 파일 | 내용 |
|---|---|
| `<task>-plan.md` | 승인된 계획 전문 |
| `<task>-context.md` | 핵심 파일, 의사결정, 의존성. `Last Updated` 포함 |
| `<task>-tasks.md` | 단계별 체크리스트 |

설계 스펙이 따로 있으면 `<task>-design.md` 를 더한다.

## 규칙

- 새 태스크를 시작할 때 `dev/active/` 에 만든다.
- 이어서 할 때는 `dev/active/` 를 먼저 확인하고 세 파일을 모두 읽는다.
- 끝나면 `dev/completed/` 로 옮기고, 맨 앞에 완료 기록을 남긴다.
  계획과 실제가 갈라졌으면 **갈라진 사실을 적는다.** 계획서를 사후에
  현실에 맞게 고치면 안 된다. 그러면 무엇을 계획했고 무엇이 실제로
  일어났는지가 사라진다.
