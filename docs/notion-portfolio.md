## 1. 왜 만들었나 (문제)

바쁜 일상에 밀려 세상이 어떻게 돌아가는지 확인할 시간이 없었습니다.
그래서 "내가 매일 챙겨보고 싶은 뉴스만, 알아서 정리해 주는 리포트"를 직접 만들었습니다.

풀고 싶었던 3가지:
1. 매일 여러 사이트를 돌며 읽는 반복 노동을 없애기
2. 홍보성·중복 기사 같은 노이즈를 걷어내기
3. 그중 진짜 읽을 가치가 있는 것만 골라 요약받기

여기서 한 걸음 더 나아가, 나만 쓰는 게 아니라 남들도 포크해서 자기 계정으로 똑같이 돌릴 수 있게 개인화(관심 키워드·커스텀 소스·Notion 저장)까지 넣었습니다.

## 2. 무엇을 만들었나 (결과)

- 12개 RSS 소스(경제·사회·연예·기술블로그)를 무인 수집 (뉴스는 최근 24시간분만)
- 홍보·중복을 결정론적 규칙으로 선(先) 필터링 후, 애매한 판단만 AI에 위임
- 카테고리별 AI 흐름 요약 + "읽을 가치" 판정
- 탭·카테고리·검색이 되는 인터랙티브 HTML 리포트로 발행 (GitHub Pages)
- 텔레그램으로 하루 3회 자동 전달 (아침=전체 브리핑, 점심·저녁=새로 뜬 소식만, 중복 없음)
- 마음에 드는 기사는 원클릭으로 Notion에 카드 저장
- 매일 쌓인 통계를 주간 트렌드 리포트로 자동 집계 (급상승 키워드·분야별 흐름 요약)
- 실패하면 스스로 멈추고 GitHub Issue 자동 생성

|------|-----|

## 3. 아키텍처 / 파이프라인

```
Cron 하루 3회 (08:30·13:07·18:07 KST)
      │
      ▼
[12개 RSS 소스]
      │  collect.py — 수집 + 홍보/중복 규칙 필터 + 카테고리 분류
      │              (뉴스는 최근 24시간분만; 기술블로그는 시간 필터 제외)
      ▼
[raw JSONL]  ← 전 소스 실패 또는 0건이면 exit 1 (스스로 중단)
      │  report.py — 카테고리별 AI 흐름요약 · 읽을가치 판정 (Claude, OAuth)
      │              ※ 아침(그날 첫 실행)에만. 점심·저녁은 AI 생략
      ▼
[AI 캐시]  ← 콘텐츠 서명(기사 hash 집합) 기준 저장, 동일 입력이면 재호출 0
      │
      ├─▶ [인터랙티브 HTML 리포트] → GitHub Pages 발행
      │
      ├─▶ 텔레그램 발송 (아침=전체 브리핑 / 점심·저녁=새 헤드라인만, seen 으로 중복 제거)
      │
      └─▶ (선택) 원클릭 → Notion 카드 저장 (Vercel 서버리스 함수)
```

데이터 페이로드 변형: WB(웹) → DB(원본 JSONL) → TB(정제 테이블) → FL(리포트)

> 노션에 붙일 때: 위 코드블록 대신 docs/pipeline-diagram.html 을 캡처해 이미지로 넣으면 더 깔끔합니다.

## 4. 주간 트렌드 리포트 (자동 집계)

매일 리포트를 만들 때 실행 통계를 스냅샷(`data/stats/*.json`)으로 남겨 두고,
매주 월요일 08:40(KST)에 최근 7일치를 다시 집계해 주간 트렌드 리포트를 만듭니다.

설계 포인트: 주간 리포트는 뉴스를 다시 수집하지 않습니다. 이미 매일 쌓아 둔 통계와 AI 요약 캐시만 재활용해 집계하므로, 추가 수집도 추가 AI 비용도 없습니다. ("한 번 만든 데이터를 재사용한다"는 파이프라인 설계 원칙의 연장선)

주간 리포트에 담기는 것:
- 분야별 주간 볼륨 (경제·사회·연예·실무 누적 수집량)
- 일자별 추이 표 (날짜 x 카테고리 매트릭스)
- 분야별 급상승 키워드 (주간 빈도, 막대 시각화)
- 분야별 "이번 주 흐름" AI 요약 (매일 캐시된 요약을 종합)

### 실제 출력 예시 (분야별 주간 흐름 요약)

- 경제: 유가 급등발 물가 상승이 소비심리 위축으로 이어지며 내수 부진 신호가 뚜렷. 미 CPI 상승에 따른 글로벌 금리 경직화로 거시 압박 심화. 금융권 구조 개편도 본격화.
- 사회: 등록금 지원 정책이 입시 지형에 즉각 영향을 주며 교육 양극화 가시화. 인사 검증에서 도덕성 논란 부각. 생성형 AI가 범죄 도구로 악용되는 신종 문제 대두.
- 연예: 글로벌 스타 내한·국내 신작으로 산업 활성화. 아시아 최대 방송영상마켓으로 시장 인프라 확대. AI 음원 저작권 문제로 산업 구조 전환기 진입.
- 실무: AI/LLM이 개발 전 과정에 편입되며 초점이 "모델 성능"에서 캐시 최적화·배포 검증·근거 제어 같은 운영 안정성으로 이동.

> 요약은 실제 리포트(docs/weekly.html)에서 뽑은 출력입니다. 노션에는 위 4줄을 인용(콜아웃) 블록으로 넣으면 "결과물이 실제로 돈다"는 인상을 줍니다.

## 5. 텔레그램 자동 발송 (전달 완성)

"수집→정제→요약→발행"에서 끝나지 않고 **전달**까지 자동화해 파이프라인을 완결했습니다. 매일 만든 브리핑을 텔레그램으로 하루 3회 받아봅니다.

핵심은 **증분 발송**입니다. 하루 3회 보내되 같은 기사를 반복해서 보내지 않습니다.

- **아침(그날 첫 실행)**: AI가 큐레이션한 전체 브리핑 (요약 + 읽을 가치 근거)
- **점심·저녁**: 그 사이 새로 뜬 기사 헤드라인만. AI를 아예 호출하지 않아 **비용 0**
- **중복 제거**: `data/seen_{날짜}.json`에 발송한 기사 hash를 누적 기록 → 이미 본 기사는 다시 보내지 않음
- **자동 리셋**: 날짜가 바뀌면 다시 아침 전체 브리핑부터 시작

설계 의도: "전체 vs 증분", "AI vs 규칙", "비용 vs 품질"의 경계를 시간대별로 다르게 둬서, 아침엔 품질(AI 큐레이션)을, 낮엔 속도·비용(규칙 기반 헤드라인)을 택했습니다.

기술적으로는 의존성 0(표준 라이브러리 `urllib`만)으로 구현하고, 토큰이 없으면 조용히 스킵해 포크해도 파이프라인이 깨지지 않게 했습니다.

## 6. 설계 하이라이트 (기술 면접용)

### 사람 / 기계 / AI 경계 설계 (핵심 의사결정)

무엇을 규칙으로 처리하고 무엇을 AI에 맡길지 명확히 나눠, 비용과 재현성을 동시에 잡았습니다.

| 역할 | 담당 | 근거 |
|------|------|------|
| 기계 (Python) | 수집·파싱·중복제거·홍보 규칙 필터·카테고리 분류·품질검증·발행 | 결정론적, 무료, 재현 가능 |
| AI 보조 (Claude) | 규칙 통과분의 흐름 요약·읽을 가치 판정 | 규칙으로 애매한 것만, 카테고리당 1회 |
| 사람 (나) | 무엇을 열어 읽을지, 주간 회고로 규칙 개선 | 최종 판단은 사람 |

### 비용 통제

- 노이즈를 규칙으로 먼저 90% 가까이 제거한 뒤에만 AI 호출 → 입력 토큰 최소화
- AI 호출은 카테고리당 1회로 묶음. 하루 3회 발송이지만 **AI는 아침 1회만** (점심·저녁은 규칙 기반 헤드라인) → 발송 횟수를 늘려도 비용은 그대로
- 경량 모델(claude-haiku) 사용

### 콘텐츠 서명 기반 캐시 (재현성 + 비용)

- AI 판정 결과를 "그날 그 카테고리 기사 집합의 hash"를 서명으로 삼아 저장
- 같은 기사면 재사용(비용 0), 새 기사가 들어오면 서명이 달라져 자동 재판정
- 부수 효과로, 같은 날 재수집 시 캐시된 픽의 위치 인덱스가 어긋나는 잠재 버그도 차단 (집합이 완전히 같을 때만 재사용하므로 인덱스가 항상 유효)

### 데이터 신선도 (카테고리별 차등)

- 뉴스(경제·사회·연예)는 최근 24시간 기사만 → 아침 브리핑이 "밤사이 소식" 위주가 되게
- 발행시각이 있는 소스만 필터하고, 없는 소스(일부 언론 RSS)는 유지 → 과도한 누락 방지
- 기술블로그·커스텀 소스는 드물게 발행되므로 시간 필터에서 제외 (실무 카테고리가 비지 않게)

### 결정론적 품질 검증 (V3 체크리스트, 매 실행 기록·노출)

1. 소스별 수집 건수 (0건이면 차단 의심)
2. 홍보 필터 제거 건수/율
3. 중복 제거 건수
4. 빈 응답/전 소스 실패 감지 → exit 1
5. 카테고리 분포
6. AI 판정 호출 건수·토큰·추정 비용

이상 징후가 있으면 잘못된 리포트를 내보내는 대신 스스로 멈추고 Issue를 생성합니다.

이 체크리스트는 `data/quality_{날짜}.json`으로 커밋돼 재현·추적 가능하며(기존엔 실행 로그에만 출력돼 수십 일 뒤 휘발됐음), 리포트 하단에 '품질 검증 기록' 섹션으로도 노출됩니다. 즉 "매 실행 자가진단한다"가 문서상 주장이 아니라 git 히스토리와 화면에 남는 산출물로 증명됩니다.

### 무인 운영 / 실패 복구

- GitHub Actions cron으로 하루 3회 자동 실행 (그날 첫 실행 여부를 seen 파일로 판별해 AI 실행/스킵 분기)
- 자동 커밋 push가 동시 실행 경쟁으로 거부되면 rebase 후 재시도 (하루 여러 번 도는 워크플로의 필수 안전장치)
- 실패 시 GitHub Issue 자동 생성으로 알림
- cron은 best-effort라 발송이 지연·누락될 수 있음을 인정하고(수십 분~수 시간), 실행 로그(`gh run`)와 품질 기록으로 원인을 결정론적으로 진단할 수 있게 설계 (예: 예정 18:07 슬롯이 지연돼 22:46에 발송된 사례를 로그로 특정)
- 개인값(토큰·키워드·소스)은 전부 시크릿/환경변수로 분리 → 포크만 하면 동작

## 8. 트러블슈팅 / 배운 점 (면접 대비)

> 노션에서 각 항목을 토글(▸)로 넣으면 깔끔합니다. 모두 실제로 겪고 해결한 이슈입니다.

- 결정: 왜 전부 AI에 맡기지 않았나
  → 비용·재현성 문제. 규칙으로 처리 가능한 건 규칙으로, AI는 "판단"이 필요한 곳에만.
- 이슈: 특정 소스가 조용히 0건을 반환하면 리포트 품질이 무너짐
  → 소스별 건수 검증 + 전 소스 실패 시 exit 1로 잘못된 발행 자체를 차단.
- 이슈: 하루 3회로 늘리자 같은 날 재수집 시 (1) 캐시가 날짜 기준이라 새 기사가 안 잡히고 (2) 캐시된 픽의 위치 인덱스가 새 기사 목록과 어긋남
  → 캐시 키를 "기사 hash 집합 서명"으로 바꿔, 새 기사가 있으면 재판정·없으면 재사용. 인덱스 드리프트도 동시 해결.
- 이슈: 소스를 지웠는데 지난 캐시에 남은 요약이 발송에 딸려 옴(유령 데이터)
  → 그날 선별 기사가 0건인 카테고리는 발송에서 제외하도록 수정.
- 이슈: 하루 여러 번 도는 워크플로에서 자동 커밋 push가 "remote가 앞섬"으로 거부(rejected)
  → 커밋 후 rebase → push 재시도 루프로 경쟁 상황 흡수.
- 이슈: 뉴스 24시간 필터를 걸자 발행시각을 안 주는 일부 언론 RSS가 통째로 누락될 위험
  → 발행시각이 "있을 때만" 필터하고 없으면 유지. 기술블로그는 필터 자체 제외.
- 한계 인정: 키워드 트렌드는 형태소 분석기 없이 단순 토큰+불용어 (투명·경량, 정교화는 후속 과제).
