Daily Brief 자동화 파이프라인

하루 3회(08:30·13:07·18:07 KST), 뉴스·기술블로그와 내가 지정한 커스텀 소스를 자동 수집·정제해 AI 요약 리포트로 내보내고 텔레그램으로 전달하는 무인 데이터 파이프라인이자, 브라우저에서 키워드로 걸러 보고 고른 기사만 원클릭으로 Notion에 저장하는 개인 뉴스 리더. 수집·필터·검증은 스크립트가, 요약·판정은 규칙을 통과한 뉴스에 한해 Claude(OAuth)가, 최종 선택은 사람이 맡는다. 아침엔 전체 브리핑, 점심·저녁엔 새로 뜬 소식만 보내는 증분 발송으로 중복 없이 받아본다. GitHub Actions cron으로 무인 갱신되며, 오픈소스 템플릿으로 누구나 포크해 자기 것으로 쓸 수 있다.

왜 이렇게 만들었나

매일 뉴스·기술블로그를 훑는 데 시간이 들고, 홍보·중복 기사가 섞여 신호 대 잡음이 나빴다. 문제는 수집이 아니라 "무엇을 읽을지" 자동으로 좁히기였다.

"전부 AI로 요약하면 간단하지만, 매일 137건마다 호출하면 토큰 비용이 감당되지 않는다."

그래서 역할을 나눴다. 결정론적으로 걸러낼 수 있는 것(홍보·중복·분류)은 규칙이 무료로 처리하고, 규칙으로 애매한 판단(흐름 요약·읽을 가치)만 규칙을 통과한 항목에 한해 AI에 넘겼다. 항목마다가 아니라 카테고리당 1회만 호출하도록 배치했다.

137건 → 4회AI 호출 · 일 $0.14

이 경계가 비용을 통제하고, 품질은 매 실행 6개 지표(소스 성공률·홍보 제거·중복·빈응답·분포·비용)로 검증한다. 이상하면 스스로 멈추고 이슈를 남긴다. 이 지표는 quality_{날짜}.json으로 커밋돼 재현·추적 가능하며, 리포트 하단에도 '품질 검증 기록'으로 노출된다(로그 휘발 방지).

규칙 우선 · AI 보조 · 사람 판단

데이터 흐름

Cron이 트리거하면 Python이 수집·적재·필터·검증·발행을 담당하고, 규칙을 통과한 항목만 Claude가 요약·판정한다(주황 핸드오프). 이 경계 설계가 토큰 비용을 최소화한다.

어떻게 동작하나

사람·기계·AI의 역할을 명확히 나눈 것이 이 프로젝트의 핵심 설계다.

기계 · Python

  • RSS 12소스 + 내 커스텀 소스 수집
  • 홍보·중복 규칙 필터 + 분류 (뉴스 24h)
  • 텔레그램 증분 발송 (발송 hash 추적)
  • V3 품질 게이트(exit 1) · 지표 quality_*.json 기록·노출

AI 보조 · Claude

규칙으로 애매한 뉴스만 위임(내소스 제외). 카테고리당 1회 호출로 흐름 요약과 읽을 가치를 판정해 비용 최소화(일 ~$0.14). Claude Code OAuth로 구독 재사용, API 키 불필요.

운영 · 무인

GitHub Actions cron이 하루 3회(08:30·13:07·18:07 KST) 실행, 실패 시 이슈 자동 생성. cron은 best-effort라 지연·누락이 있을 수 있는데, 실행 로그와 품질 기록으로 원인을 결정론적으로 진단할 수 있게 설계했다. 아침엔 전체 브리핑, 점심·저녁엔 새로 뜬 소식만 텔레그램으로 증분 발송(AI는 아침 1회만). 산출물은 GitHub Pages 리포트 + 주간 트렌드. Notion 저장은 사람이 고른 카드만 원클릭(Vercel 서버리스 함수, 토큰은 서버에만).

브라우저에서 바로 (개인 도구)

읽기 전용 리포트가 아니라, 사용자가 화면에서 직접 조작하는 개인 뉴스 리더. 설정은 각자 브라우저에 저장돼 사람마다 다르게 동작한다.

🔖 관심 키워드

페이지에서 키워드를 추가·삭제하면 관련 기사만 즉시 필터. 파일 편집·커밋 없이 브라우저(localStorage)에 저장.

📌 내 소스

블로그·사이트 주소를 화면에서 추가/삭제하고 즉시 수집. 네이버 블로그·티스토리·워드프레스는 홈 주소만 넣어도 자동 RSS 변환.

☁️ 원클릭 Notion

고른 카드를 버튼 한 번으로 Notion에 저장. Notion·GitHub 토큰은 서버리스 함수 환경변수에만, 페이지엔 없음(APP_KEY로 보호).
