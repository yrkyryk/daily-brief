왜 이렇게 만들었나

매일 뉴스·기술블로그를 훑는 데 시간이 들고, 홍보·중복 기사가 섞여 신호 대 잡음이 나빴다. 문제는 수집이 아니라 "무엇을 읽을지" 자동으로 좁히기였다.

"전부 AI로 요약하면 간단하지만, 매일 137건마다 호출하면 토큰 비용이 감당되지 않는다."

그래서 역할을 나눴다. 결정론적으로 걸러낼 수 있는 것(홍보·중복·분류)은 규칙이 무료로 처리하고, 규칙으로 애매한 판단(흐름 요약·읽을 가치)만 규칙을 통과한 항목에 한해 AI에 넘겼다. 항목마다가 아니라 카테고리당 1회만 호출하도록 배치했다.

137건 → 4회AI 호출 · 일 $0.14

이 경계가 비용을 통제하고, 품질은 매 실행 6개 지표(소스 성공률·홍보 제거·중복·빈응답·분포·비용)로 검증한다. 이상하면 스스로 멈추고 이슈를 남긴다.

규칙 우선 · AI 보조 · 사람 판단

데이터 흐름

Cron이 트리거하면 Python이 수집·적재·필터·검증·발행을 담당하고, 규칙을 통과한 항목만 Claude가 요약·판정한다(주황 핸드오프). 이 경계 설계가 토큰 비용을 최소화한다.

어떻게 동작하나

사람·기계·AI의 역할을 명확히 나눈 것이 이 프로젝트의 핵심 설계다.

기계 · Python

  • RSS 12소스 수집(feedparser)
  • 홍보·중복 규칙 필터 + 분류
  • 멱등 적재, 중복 차단
  • V3 품질 게이트, 이상 시 exit 1

AI 보조 · Claude

규칙으로 애매한 항목만 위임. 카테고리당 1회 호출로 흐름 요약과 읽을 가치를 판정해 토큰 비용을 최소화(일 ~$0.14). Claude Code OAuth로 구독 재사용, API 키 불필요.

운영 · 무인

GitHub Actions cron이 매일 08:30 실행. 실패하면 이슈를 자동 생성하고, 산출물은 GitHub Pages 리포트와 Notion 카드뉴스로 발행된다.
